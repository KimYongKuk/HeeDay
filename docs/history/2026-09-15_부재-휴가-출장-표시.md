## 배경

히의 요구는 "외부 출장 건이 월 캘린더에서 구분되면 좋겠다"였고, 처음 떠올린 안은 날짜 숫자 옆의 작은 아이콘이었다. 첫 분석에서는 이것을 **할 일의 출장 플래그**(중요 ★와 같은 모양)로 받는 방향을 제안했다. 그런데 요구를 다시 확인하니 특정 업무의 출장 여부가 아니라 **그 날 담당자가 자리에 있는지**(휴가·출장 등 부재 여부)를 알고 싶은 것이었다. 그래서 할 일이 아니라 날짜의 속성으로 방향을 틀었고, 비슷한 자리를 차지하고 있던 휴관일 기능을 확장하기로 했다.

## 핵심 결정과 이유

- **할 일 플래그가 아니라 날짜 속성** — 첫 제안(중요 ★와 같은 `tasks.trip` 플래그)은 요구를 다시 읽고 버렸다. 부재는 할 일이 없는 날에도 존재하고, 할 일을 옮긴다고 따라 움직이면 안 된다.
- **휴관일 테이블에 종류를 얹지 않고 `absences` 를 따로 뒀다** — 세 가지가 달랐다. (1) 부재는 기간 단위라 3일 연차가 한 줄이어야 하는데 `closure_days` 는 날짜당 한 행. (2) `uq_closure_days_date` 고유 제약 때문에 휴가 기간 안의 공휴일과 충돌한다. (3) 휴관은 "기관이 닫힘"(빨강, 공휴일 시드·API 가 채움)이고 부재는 "기관은 열렸고 사람이 없음"이라 같은 색으로 보이면 오독된다. 화면만 하나로 합쳤다.
- **담당자 컬럼 없음** — 로그인 없는 단일 직원 구조. 뒤에 다중 직원이 생기면 그때 붙인다.
- **마법사에서는 휴관일과 같은 취급** — 부재일도 "일할 수 없는 날"이므로 경고를 내고 균등·반복 배치가 건너뛴다. 경고 우선순위는 기간 외 > 휴관 > 부재 > 주말. 기존 원칙대로 배치된 날짜를 옮기지는 않는다.
- **placement 헬퍼는 선택 인자로 확장** — `closures: Set` 시그니처를 `{closures, absences}` 객체로 바꾸는 안도 있었지만 호출부·테스트 전부가 흔들려서, 기본값 빈 집합인 마지막 인자로 붙였다. 부재를 안 넘기면 기존 동작과 완전히 같다.
- **입력 지점 두 곳** — 주 입력은 휴관·부재 화면(기간 입력), 보조 입력은 날짜 셀 `+` 팝오버. "9월 23일에 출장이 잡혔다"는 순간 메뉴를 찾아가는 것보다 그 날짜에서 바로 표시하는 편이 자연스럽다. 별도 `/absences` 메뉴는 만들지 않았다.
- **색은 프로그램 팔레트와 무관한 고정 호박색** — 날짜 옆 배지는 여러 프로그램을 합쳐 보여주는 자리라 프로그램 색을 쓰면 오해가 생긴다. 오늘(브랜드 파랑)·휴관(빨강)과도 겹치지 않는다. `amber` 프로그램 칩 배경(`#fbefd6`)보다 훨씬 옅게 잡았다.

## 여기가 어려웠다

- **셀 배경 우선순위**: 휴관 > 부재 > 오늘 > 주말. 오늘은 숫자에 파란 원이 따로 있어 배경을 양보해도 식별된다. 휴관일 이름이 있는 날은 부재 이름을 생략하고 아이콘만 남긴다(`AbsenceBadge label={!holidayName}`). 22px 높이 한 줄에 둘 다 넣으면 잘린다.
- **겹치는 부재**: 출장과 휴가가 같은 날에 걸치면 `absenceByDate()` 는 먼저 나열된 행(시작일 오름차순, id 오름차순)을 쓴다. API 는 겹침을 막지 않는다. 막으면 "출장 뒤에 이어서 연차"처럼 하루 경계가 애매한 입력이 번거로워진다.
- **범위 조회는 겹침 조건**: `listAbsences` 의 조건은 `end_date >= from AND start_date <= to` 다. 시작일만 범위로 걸면 전월 말에 시작해 이번 달로 이어지는 출장이 빠진다.
- **우측 패널의 오늘 부재는 별도 조회**: 월 보기가 다른 달을 보고 있으면 화면 범위에 오늘이 없어서 `useAbsences({from: today, to: today})` 를 따로 부른다.
- **`lucide-react` 아이콘 이름**: `Palmtree` 가 `TreePalm` 으로 개명된 버전이다. 둘 다 존재하지만 새 이름을 썼다.
- **QuickAdd 팝오버 닫힘**: 부재 모드에서 닫으면 다음에 열 때 할 일 모드로 돌아가야 해서 `onOpenChange` 를 `close()` 로 감쌌다.
- **마이그레이션 파일명**: drizzle-kit 이 만든 `0003_slim_ma_gnuci.sql` 을 `0003_absences.sql` 로 바꾸고 `drizzle/meta/_journal.json` 의 tag 도 같이 고쳤다. 둘이 어긋나면 migrate 가 파일을 못 찾는다.

## 검증

- `pnpm test` 36 통과(부재 관련 3건 추가), `pnpm lint`, `pnpm typecheck`, `pnpm build` 모두 통과.
- 로컬 MariaDB 에 `pnpm db:migrate` 적용 확인.
- API 를 curl 로 확인: 생성 2건, 범위 조회, 종료일이 시작일보다 앞선 입력은 400 `VALIDATION`. 확인 후 테스트 행은 삭제.
- Playwright 로 월·주·모바일 월·휴관·부재 화면·날짜 셀 팝오버(부재 모드) 스크린샷 확인. 콘솔 오류 0건. 9월 24일처럼 부재와 공휴일이 겹친 날은 아이콘만 남고 휴관 이름이 우선하는 것 확인.
- 마법사 3단계의 부재 경고·미니 달력 표시는 타입체크와 단위 테스트로만 확인했고 화면 캡처는 하지 않았다.

## 남은 것

- **운영 DB 마이그레이션 필요**: push 전에 `pnpm db:migrate:prod`. 그 다음 배포(15 크레딧).
- 여러 날짜에 걸친 부재는 캘린더에서 날마다 따로 배지가 붙는다. 주 보기에서 한 줄로 이어 그리는 것은 하지 않았다.
- 부재 수정(PATCH)은 없다. 잘못 넣었으면 지우고 다시 넣는다.
