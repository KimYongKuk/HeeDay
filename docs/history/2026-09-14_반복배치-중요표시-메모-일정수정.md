## 핵심 결정과 이유

- **반복은 규칙이 아니라 회차로 한 번 펼친다** — "회차는 3단계 안에서만 존재하고 템플릿·DB 에 세션 개념이 없다"는 결정을 지키기 위해. `repeatDates()` 가 날짜 배열을 만들고 `addOccurrences()` 로 넣는 것이 전부라 스키마 변경이 없고, 펼친 뒤엔 각 회차를 평소처럼 옮기고 지운다. 반복 규칙을 저장해 뒀다가 다시 펼치는 방식은 회차 모델과 충돌해서 버렸다.
- **매달은 두 가지 다 넣었다** — "매월 15일"과 "매월 둘째 수요일" 중 히가 어느 쪽을 뜻하는지 확인하지 못했고, 복지관 프로그램은 후자일 가능성이 커서 둘 다 제공한다. 없는 날(31일, 다섯째 주)은 마지막 날로 당기지 않고 **건너뛴다**. 당기면 "매월 31일"이 30일·28일에 섞여 규칙이 안 보인다.
- **중요는 boolean 하나, 태스크 단위** — 상/중/하 우선순위나 양식 항목 기본값은 넣지 않았다. 담당자가 혼자라 프로그램 간 비교가 아니라 "이번 주에 꼭 해야 하는 것"이 관심사이고, 별 하나면 등록할 때·달력 보다가 두 시점을 다 커버한다. 기존 `required`(제외 불가)와는 의미가 달라 겹쳐 쓰지 않았다. 회차별로 다르게 표시할 수 있도록 마법사 `important` 는 드래프트 키(회차 키) 단위.
- **메모는 태스크가 아니다** — 날짜·완료·캘린더 노출이 없다. 날짜 없는 할 일(인박스)로 만들면 "할 일은 항상 날짜와 프로그램에 속한다"는 모델이 흐려지고 현황 집계에 예외가 생긴다. 못한 일을 태스크로 승격하고 싶으면 날짜 셀 `+` 로 직접 만든다.
- **태그는 `#` 피커, 본문 파싱 없음** — 히가 제안한 "메모 끝에 # 태깅"을 피커로 구현했다. `#스마트폰 활용교실` 처럼 이름에 공백이 있고 이름을 바꾸면 링크가 끊기므로 텍스트 파싱은 버리고 `program_id` 를 저장한다. 첫 구현의 `Select` 는 등록 시에만 쓸 수 있어 항목 하단으로 옮기면서 같은 컴포넌트로 통일했다.
- **우측 패널 메모는 3줄 + 팝오버** — 작성기를 패널에 두면 오늘·중요·이번 주·현황 뒤에서 스크롤이 생긴다는 피드백. 최근 3건을 한 줄로만 보여주고 `+` 는 팝오버, 나머지는 `/memos` 로 보낸다.
- **일정 수정은 할 일을 건드리지 않는다** — 기간을 줄여도 마법사와 같은 규칙("경고만, 이동 없음"). 양식 스냅샷도 그대로. 자동으로 옮기면 사용자가 배치한 날짜가 조용히 바뀐다.
- **좌측 nav 순서를 바꿨다** — CLAUDE.md 에 고정돼 있던 순서에 메모를 휴관일 뒤에 넣었다. 사용자에게 보고했고 이의 없음.

## 여기가 어려웠다

- **DB 타임스탬프는 KST 벽시계를 `Z` 로 돌려준다.** 풀이 `timezone: 'Z'` + `dateStrings` 라 MariaDB 의 `CURRENT_TIMESTAMP`(서버 로컬 = KST 10:27)가 `"…T10:27:05Z"` 로 온다. 브라우저에서 `new Date()` 로 바꾸면 +9h 밀려 **오후 3시 이후 만든 메모가 내일 날짜로 보인다.** `MemoList.shortDate` 는 문자열에서 월/일을 그대로 자른다. `ProgramDetail` 의 등록일도 같은 이유로 `createdAt.slice(0, 10)` 이 맞다. 고치려면 `Date` 변환이 아니라 풀 설정을 봐야 한다.
- **`drizzle-kit generate` 파일명은 무작위다** (`0001_complex_mac_gargan.sql`). 이름을 바꾸면 `drizzle/meta/_journal.json` 의 `tag` 도 같이 바꿔야 `db:migrate` 가 찾는다. 이번엔 `0001_task_important`, `0002_memos` 로 바꿨다.
- **드래그 가능한 행이 `role="button"`** 이라 Playwright 의 `getByRole('button', {name:'반복 배치'})` 가 행 전체에 매칭돼 날짜 필드가 열렸다. dnd-kit 이 붙이는 역할이다. 테스트는 `button[aria-label="…"]` 로 잡을 것.
- **zsh 는 `set -- $VAR` 로 단어를 쪼개지 않는다.** 검증 중 프로그램 기간 원복이 이 때문에 실패해 DB 를 직접 고쳤다. 셸 스크립트에서 변수 분리를 믿지 말 것.
- **`programPatchSchema` 의 기간 검사는 둘 다 올 때만 본다.** 한쪽만 PATCH 하면 기존 값과의 순서를 서버가 확인하지 않는다. 다이얼로그는 항상 둘 다 보낸다. 다른 클라이언트가 한쪽만 보내면 역전될 수 있다.
- **반복 생성 시 이미 있는 날짜는 제외한다** (`taken`). 같은 규칙을 두 번 누르면 중복 회차가 안 생기지만, 날짜를 옮긴 뒤 다시 누르면 그 자리는 다시 채워진다. 의도된 동작이다.
- **`GET /api/tasks?important=1` 은 범위 파라미터를 무시한다.** 우측 패널이 어느 달을 보든 전체 미완료 중요를 보여주기 위해서다. 프로그램 필터는 클라이언트에서 건다.
- **모바일 탭이 6개.** 390px 에서 탭당 65px. 항목이 더 늘면 탭 바 자체를 다시 봐야 한다.
